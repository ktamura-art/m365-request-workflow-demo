# 依頼受付・進捗管理 業務デモ（Microsoft 365 標準機能）

部門からの依頼・課題の受付から進捗管理・可視化までを、Microsoft 365 の標準機能だけで回した場合の
操作デモです。株式会社デジライズ作成。検索インデックス除外（noindex）。

- `index.html` … デモ本体（6画面をタブ／前後ボタンで切り替え。自己完結・外部依存なし）

## デモで見せているもの

1. **現状（Excel台帳＋メール催促）** — 二重登録、`_最新_v3_修正版` の増殖、記憶頼みの催促、毎月の手集計
2. **依頼フォーム（Forms）** — スマホ入力・必須チェックで、不備のある依頼を入口で止める
3. **Teams通知** — 送信数秒後に担当チャネルへ依頼カードが自動投稿（優先度「高」はメンション付き）
4. **台帳（SharePointリスト）** — 自動採番・同時編集・変更履歴・権限管理。ステータス変更が5に反映
5. **フローの中身（Power Automate）** — トリガー→採番→リスト登録→条件分岐→通知→期限リマインド。
   ブロックをクリックすると設定が開く。**「コードが1行もない」ことを見せるのが本命の画面**
6. **ダッシュボード（Power BI）** — 受付件数／未対応／平均リードタイム／期限超過、部署別・ステータス別、
   リードタイム推移（8.5日→3.2日）、滞留リスト

画面2で送信した依頼は、3・4・6にそのまま反映されます（採番・通知・台帳・集計が連動）。

## 設計上の前提

- **標準ライセンスの範囲**で構築できる構成のみ（Premiumコネクタを使わない）
- Copilot / Copilot Studio は主役にしない（先方のライセンス状況に依存するため）
- Microsoft のロゴ・ワードマーク、サインイン画面は使用しない。Fluent の様式に寄せた
  **画面イメージ（プロトタイプ）** であることを画面上に明示
- 企業名・部署名・データはすべて架空

## 操作

- 上部タブ、下部の「前へ／次へ」、キーボードの ←→ で画面を移動
- 画面2のフォームは実際に入力・送信できる
- 画面4のステータスを変更すると画面6の数字とグラフが動く
