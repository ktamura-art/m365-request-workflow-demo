# 特注・別注依頼の受付 業務デモ（Microsoft 365 標準機能）

営業から届く「この特注はできますか」という相談の受付から、技術側の検討・客先への回答・
受注率の可視化までを、Microsoft 365 の標準機能だけで回した場合の操作デモです。
株式会社デジライズ作成。検索インデックス除外（noindex）。

- `index.html` … デモ本体（7画面をタブ／前後ボタン／←→キーで切替。自己完結・外部依存なし）

## 扱っている業務

**正式な受注処理ではありません。** 基幹システムに載る前の「特注できるか／いくらか／いつ出せるか」を
営業と技術の間で詰める工程です。Excelとメールで回りがちな隙間業務であり、M365が最も効く領域です。

## デモで見せているもの

1. **現状（Excel台帳＋メール催促）** — 二重登録、`_最新_v3_修正版` の増殖、営業からの催促、過去の類似特注が探せない
2. **特注依頼フォーム（Forms）** — 顧客・品番・数量・回答期限を必須化し、情報不足での差し戻しを防ぐ
3. **Teams通知** — 技術チャネルへ自動投稿。**同じ品番の過去の特注実績を自動検索して添付**
4. **台帳（SharePointリスト）** — 自動採番・同時編集・変更履歴。
   **「⚡ 自動入力を再生」でフローが9項目を1セルずつ書き込む様子を再生**（繰り返し可）
5. **フローの中身（Power Automate）** — トリガー→採番→登録→過去実績検索→条件分岐→通知→回答期限リマインド。
   ブロックをクリックで設定が開く。**「コードが1行もない」ことを見せるのが本命の画面**
6. **ダッシュボード（Power BI）** — 依頼件数／未回答／平均回答リードタイム（5.2→1.8日）／期限超過／
   依頼元別／ステータス構成と**受注率**／滞留リスト
7. **効率化のまとめ** — 機能別に「無くなる作業・根拠・削減時間」を一覧（月14.8時間・年約53万円）

画面2で送信した依頼は、3・4・6にそのまま反映されます（採番・通知・台帳・集計・受注率が連動）。

## 設計上の前提

- **標準ライセンスの範囲**で構築できる構成のみ（Premiumコネクタを使わない）
- Copilot / Copilot Studio は主役にしない（先方のライセンス状況に依存するため）
- Microsoft のロゴ・ワードマーク、サインイン画面は使用しない。Fluent の様式に寄せた
  **画面イメージ（プロトタイプ）** であることを画面上に明示
- 企業名・顧客名・品番・データはすべて架空（顧客は「建設A社」等の匿名表記）

## 操作

- 上部タブ、下部の「前へ／次へ」、キーボードの ←→
- 画面1は現状の再現で、クリックできる箇所はありません（明示済み）
- 画面2のフォームは実際に入力・送信できる
- 画面4のステータスを変更すると画面6の数字・グラフ・受注率が動く
